PROJECT PROTOCOL

Project setup:
Tools: IntelliJ IDEA, Maven, Temurin-21 SDK
Dependencies:
- com.fasterxml.jackson.core (JSON parsing)
- commons-io (IO utilities)
- org.postgresql (PostgreSQL JDBC Driver)
- junit (unit tests)
- org.mockito (mocking)

Architecture overview:

Handler -> Service -> Repository -> Database

When a request comes in, the Handler layer parses the HTTP request and validates the input.
The request is then forwarded to the Service layer, where the business logic and validation rules are handled.
The Service layer communicates with the Repository layer, which is responsible for database access using JDBC and SQL.
The Database layer contains the persistable data (users, media entries, ...)

The application uses a UnitOfWork pattern to manage transactions and ensure consistency.

Design decisions:
- Clear separation of concerns between layers
- Repositories contain only SQL and database logic
- Business logic is not mixed with HTTP handling
- PreparedStatements are used to prevent SQL injection
- Database constraints ensure data integrity

SOLID principles applied:

Single Responsibility Principle (SRP):
Each class has one responsibility:
- Handlers handle HTTP requests
- Services handle business logic
- Repositories handle database access

This improves maintainability and readability.

Open/Closed Principle (OCP):
- Filtering and sorting logic was implemented in a way that allows new filters or sorting options to be added without modifying existing code structure.

Unit testing strategy:

- JUnit 5 is used for writing tests
- Mockito is used to mock repositories
- No real database connections are used in unit tests

Tests cover:
- User creation and lookup
- Media CRUD operations
- Rating rules (one rating per user)
- Favorites and recommendations
- Error handling and edge cases

Lessons learned:
- Maven greatly simplifies dependency management
- SQL aggregation functions (AVG, GROUP BY) reduce application logic complexity
- Mock-based testing improves test reliability
- Database constraints prevent many runtime errors

Problems encountered:

Handling dependencies:
Initially, dependencies were stored manually in a libraries folder and had to be downloaded individually.
Solution: Migrated to Maven and defined dependencies in the pom.xml file.

Naming conventions:
Layer and class names changed multiple times during development.
Solution: Settled on consistent naming conventions for all layers.

SQL complexity:
Some SQL queries became hard to read and debug.
Solution: Split complex logic into smaller queries and helper methods.
